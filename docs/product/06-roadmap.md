# 路线图

本路线图以“完整目标设计、分阶段形成可验证能力”为原则。多系统是基础能力，不以单系统 MVP 限制产品结构；ESB 仅作为首批真实数据和评测集。

## 3. Phase 0 - 初始化与决策门禁

目标：

1. 固化产品应用定位、多系统边界、角色、流程、部署约束和验收基线。
2. 对前后端、数据、检索模型、任务机制、认证和非容器化部署给出候选方案并完成选择。
3. 形成可实现、可测试、可追溯的架构设计。
4. 完成 `knowledge-rag` 可复用资产盘点，明确可迁移、需重构和禁止迁移边界。

交付物：

1. 需求澄清、路线图、前端设计、开发原则和追溯矩阵。
2. 技术选型记录和性能权衡。
3. 系统架构、模块边界、接口、数据流和部署视图。
4. 来源项目迁移评估及迁移门禁。

验收标准：

1. P0/P1/P2、角色、端到端流程和 AC 均无关键空白。
2. 技术选型完成 2-3 方案比较并得到用户确认。
3. 架构方案得到用户确认后才进入代码实现。
4. 不以来源项目 README、禁用测试或骨架 TODO 作为可迁移成熟度证明。

## 4. Phase 1 - 多系统知识基础

当前进度：6/6，已完成并关闭。统一 `SourceLocator`、四类结构化解析、结构感知切分、S3 兼容对象存储、可恢复持久化入库任务、文档多版本、发布状态和 `system_id` 复合隔离基础模型已完成。2026-08-04 已在固定 integration 环境完成真实 PostgreSQL/Redis/MinIO、四格式持久化、双系统零泄漏、v2 发布切换和任务恢复验收，详见 `docs/development/20-phase1-integration-acceptance.md`。

功能范围：

1. 用户端/管理端独立登录表单、统一账号认证、用户 SQL 批量导入、管理员后台新增、首次改密、三角色 RBAC 和 SSO 适配边界。
2. 多业务系统管理、系统负责人配置和前台系统选择。
3. 用户端与管理后台基础导航、状态和错误处理。
4. 先定义统一 `SourceLocator`，再实现 `.docx`、文本型 `.pdf`、`.md`、`.xlsx` 的结构化解析、切分和精确引用定位。
5. 对象存储、持久化入库任务、幂等、阶段进度、失败重试和进程重启恢复。（已完成）
6. 文档版本、发布状态和基于 `system_id` 强过滤的知识隔离基础模型。（已完成）

验收标准：

1. AC-001、AC-002、AC-003、AC-009 的 Phase 1 部分通过，包括错误入口、默认密码首次改密和服务端越权测试。
2. 至少两个系统和四类样本文档完成真实持久化集成测试，并通过任务重启恢复测试。

## 5. Phase 2 - 问答与工单闭环

当前进度：4/4 功能范围和真实服务集成完成。关键词/向量召回、RRF、Embedding 索引、证据决策、可靠拒答、SSE、工单工作流、审核发布、`TICKET` 来源检索及答案/引用快照已在真实 PostgreSQL 17/pgvector、Redis、Ollama bge-m3 和 Qwen `qwen3.5-27b` 上完成 23 项组合验证。Worker 索引失败进入持久重试状态，SSE token 账号隔离/单次消费和增量引用校验均有回归。

Phase 2 尚未关闭：AC-004/AC-005 缺至少 50 条真实标注 ESB 可回答问题和无知识问题集，无法给出真实正确率、引用支持率及拒答召回率。2026-08-06 已补本地普通测试账号并完成向量降级拒答/建单浏览器链路；带引用回答、Rerank 与负责人处理/审核页面仍需已发布知识和对应角色数据。评测门禁和数据格式见 `docs/development/22-phase2-evaluation.md`。

功能范围：

1. 关键词与向量基础召回、证据组织、回答生成和来源引用。（代码、API/SSE 和真实 Qwen 增量引用流通过）
2. 证据充分性决策；不足时记录原因、拒答并自动创建内置工单。（代码、API 和真实 PostgreSQL 工单链路通过；质量指标待真实评测集）
3. 按系统分派、处理、追加、关闭、重开和审核入库。（代码、API、真实数据库集成和前端页面实现通过；业务页人工验收待补）
4. 审核发布后的知识重新索引、来源追踪和历史引用快照保留。（真实 Worker→Embedding、5 分钟内回流检索和来源退役后历史引用通过）

验收标准：

1. AC-003 至 AC-007 的 Phase 2 范围通过自动化、真实服务集成和业务页人工验收。
2. 至少 50 条 ESB 真实可回答问题达到答案正确率 >=80%、引用支持率 >=95%。
3. 真实无知识问题达到拒答召回率 >=90%，每次可靠拒答均有工单，零无引用事实答案。

## 6. Phase 3 - 质量与运营增强

## 7. Phase 4 - 内网交付与扩展

功能范围：

1. 无 Docker 的 Linux 安装、配置、systemd 进程管理、Nginx 反向代理、升级、备份和回滚流程。
2. 面向宿主机进程、PostgreSQL、Redis、对象存储和模型服务的日志、指标、告警、容量与安全加固。
3. 公司 SSO 接入准备，以及更多业务系统的运营接入流程。

验收标准：

1. AC-010、AC-012 通过，并在类生产 Linux 环境完成一次全新安装和一次回滚演练。
2. 形成系统负责人可执行的知识接入和日常运营清单。

## 8. 路线图调整规则

- 不因“首版必须简单”移除多系统边界，但允许按阶段逐步完成同一完整方案。
- 每阶段必须有独立可观察结果；未通过验收不得把问题隐藏到下一阶段。
- 模型、框架、数据库扩展、任务系统和部署方式必须先通过技术选型门禁。
- 需求优先级或阶段范围变化时，同步更新需求文档和追溯矩阵。
