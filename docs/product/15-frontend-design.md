# 前端设计：企业内部智能客服 Agent

## 1. 产品形态

```text
产品类型：企业内部 Web 工具，包含用户登录后的问答端、个人工单区和独立登录的管理后台
主要场景：选择业务系统后问答；核验引用；跟踪工单；管理文档、知识、系统和用户
目标用户：普通内部用户、系统负责人、平台管理员
使用频率：普通用户按需使用；负责人和管理员高频重复操作
主要设备：公司桌面浏览器
屏幕重点：1280px-1920px 桌面端；移动端保留问答、引用和工单跟踪基本流程
```

产品第一屏直接进入可用问答体验，不制作营销落地页。

## 2. UI 风格参考

| 参考 | 借鉴点 | 不采用点 |
| --- | --- | --- |
| ChatGPT 对话界面 | 清晰的消息流、输入区、会话切换和引用展开方式 | 不照搬大面积留白和面向公众产品的引导内容 |
| Dify / RAGFlow 管理界面 | 知识库、文档处理状态、检索配置和调试流程 | 不把过多技术参数暴露给普通用户，不堆叠卡片 |
| Linear | 克制视觉、紧凑列表、快捷状态切换和明确焦点 | 不使用过暗或紫蓝主导的品牌风格 |
| GitHub | 表格、筛选、权限、审计和状态标签的成熟表达 | 不复制复杂的全站信息架构 |

组合方向：用户端采用成熟会话模式，管理端采用安静、紧凑、适合扫描和重复操作的后台模式。

## 3. 设计关键词

```text
整体气质：可信赖、克制、专业、工作导向
视觉关键词：中性底色、清晰层级、低装饰、来源可见、多状态可辨
交互关键词：快速选择、即时反馈、逐层展开、批量处理、错误可恢复
信息密度：问答页中等；管理页中高
专业感/亲和力：专业优先，文案直接但不过度技术化
品牌感：弱品牌、强任务，避免用单一颜色统治界面
```

## 4. 色彩策略

```text
主色：深青绿色，用于主要命令、焦点和当前选择
辅助色：清晰蓝色，用于链接、引用和信息状态
背景色：近白中性灰；内容表面使用白色
文本色：接近黑色的中性深灰，不使用大面积深蓝/Slate
状态色：绿色成功、红色错误、琥珀色警告、蓝色信息
需要避免：紫蓝渐变、米色/棕色主导、低对比灰字、大面积同色卡片
```

所有实现颜色必须引用 `15-frontend-design-tokens.json`。

## 5. 信息架构与布局

### 5.1 全局导航

- 桌面端采用固定左侧导航，包含问答、我的工单以及按角色显示的知识、工单、业务系统、用户和审计入口。
- 页面顶部只保留上下文标题、业务系统选择、全局搜索/通知入口和账号菜单。
- 普通用户不显示无权限的管理导航；直接访问无权限路由时展示明确的权限不足状态。
- 用户端账号菜单不提供管理后台入口；管理员从独立管理登录页进入，服务端仍需校验入口允许的角色。

### 5.2 问答页

- 业务系统选择器位于会话区域顶部并保持可见，切换系统前明确提示会话上下文变化。
- 消息流占主区域，输入工具栏固定在底部且尺寸稳定，不因 loading 或附件状态产生布局跳动。
- 引用以内联标记和右侧抽屉展示，抽屉显示文档、版本、页码/标题/工作表位置和原文片段。
- 无法回答时直接展示工单编号、负责人/待分派状态和查看工单命令，不用功能介绍文案占位。

### 5.3 管理后台

- 页面以全宽内容区、筛选栏、工具栏、表格和详情抽屉为主，不把整个区块做成浮动卡片。
- 文档、工单、用户、系统和审计列表使用分页、筛选、排序和稳定列宽。
- 上传、解析、索引和通知等异步任务在表格中显示状态、进度、时间和可执行操作。
- 编辑使用独立页面或抽屉；只有确认、少量字段编辑使用弹窗。

### 5.4 登录与账号管理

- 用户登录页与管理员登录页使用不同标题、入口和登录接口，避免普通用户误入后台。
- 两端表单都包含账号、密码、提交状态和通用错误，不在错误信息中暴露账号是否存在或角色类型。
- 批量导入用户首次使用默认密码登录后，必须进入独立改密页；改密完成前不渲染问答、工单或后台导航。
- 管理员账号在后台使用表单新增；用户账号首版只展示导入结果、状态、首次改密状态和禁用/重置操作，不提供逐个新增表单。

### 5.4 响应式

- `>=1024px`：完整侧栏、主内容和引用抽屉。
- `768px-1023px`：侧栏可折叠，引用抽屉覆盖显示。
- `<768px`：底部或折叠菜单，问答单列；管理表格允许横向滚动并优先保留关键列。
- 字体大小不随视口宽度缩放；长文件名、系统名和错误消息必须换行或省略并提供完整查看方式。

## 6. 卡片与组件风格

```text
卡片：只用于独立重复项、对话状态摘要和模态工具；禁止卡片嵌套卡片
圆角：普通组件 4-6px，卡片和弹窗不超过 8px
边框/阴影：默认细边框；阴影只用于弹窗、菜单和抽屉层级
按钮：熟悉命令优先图标或图标+文字；陌生图标必须有 tooltip
表单：标签清楚、内联校验、帮助信息按需出现，提交期间不改变按钮尺寸
表格：稳定列宽、粘性表头、行级菜单、批量选择和分页
状态：使用颜色、图标和文本共同表达，不只依赖颜色
图标：技术选型阶段确定现有图标库；有成熟图标时禁止手绘 SVG
```

## 7. 关键交互状态

| 状态 | 处理原则 |
| --- | --- |
| loading | 使用局部骨架、进度或固定尺寸 spinner；不清空已有内容，不引发布局跳动 |
| empty | 给出与当前角色相关的首要操作，不展示大幅插画或功能说明 |
| error | 说明发生位置、可执行恢复动作和错误追踪 ID，不暴露内部堆栈 |
| success | 就近反馈；批量或异步操作显示结果数量和失败项 |
| disabled | 保持尺寸和可读标签，通过 tooltip 或邻近文案说明原因 |
| hover/focus/active | 键盘焦点始终清晰；hover 不移动组件或改变布局 |
| 表单校验 | 字段失焦或提交时校验，首个错误可聚焦，服务端错误映射到对应字段 |
| 危险操作 | 删除、下线、重建索引和角色变更必须确认并说明影响范围 |
| 权限不足 | 展示受限对象和可联系角色，不渲染可执行危险命令 |
| 网络异常 | 保留用户输入，允许重试；可能重复写入的操作使用幂等处理 |
| 降级/拒答 | 明确当前不可可靠回答，并展示工单或重试状态，不伪装成正常答案 |

## 9. 组件与资源策略

```text
基础组件：Ant Design 6，通过主题配置映射本项目 token；按模块使用，不以默认品牌色覆盖设计规范
图标库：Lucide React，要求 tree-shaking，禁止与 Ant Design 图标混用
图表库：仅分析页需要，必须动态导入并通过技术选型门禁
表格方案：首版使用 Ant Design Table，必须采用服务端分页、筛选、排序和稳定列宽；大数据虚拟化另行评估
文档预览：按文件类型和权限按需加载，不进入首屏包
富文本/编辑器：首期优先结构化表单或 Markdown；若引入编辑器需单独选型
媒体策略：不使用装饰性图库；文件图标和真实文档预览服务任务本身
按需引入：禁止组件库和图标库全包导入
懒加载：管理路由、分析、文档预览、编辑器和大表格按路由/组件拆分
```

## 10. 需要避免

1. 营销式首屏、超大标题、装饰性渐变、光斑和无业务意义插画。
2. 页面区块全部浮成卡片，或在卡片内部继续嵌套卡片。
3. 用同一青色覆盖背景、按钮、状态和图表，形成单一色调界面。
4. 在普通用户界面暴露 top-k、阈值、模型名等运营参数。
5. 用颜色作为唯一状态信号，或使用低对比度文字。
6. loading、长系统名、长文件名或动态状态导致工具栏、按钮和表格跳动。
7. 首屏加载文档预览、图表、编辑器或完整管理模块。
